# R6 — local assistance and voice drafts

R7 update24/10/2026: the current Web uses the editable named-draft flow described in `voice-prescription-contract.md`. Unmatched names can be saved and edited without transcript-only correction. Uncoded medicine requires the doctor's explicit manual-review acknowledgement and complete instructions before release. The strict legacy draft endpoint remains available; statements below describe the original R6 behavior.

Base907cba2; worktree `ai-r6`. No commit/push requested in R6. Root develop remains unchanged. The tested R6 audit runtime is now deployed locally; see r6-acceptance-2026-10-21.md for exact limits.

Clinical assistant primary engine: local evidence retrieval over immutable, versioned source excerpts, with department scope and DOCTOR review. No cloud model, generated diagnosis/dose, DOM scraping, demo consultation IDs or medical fallback. Retrieval answers quote their sources; no relevant approved source is an explicit insufficient-evidence/unavailable result. This supports source-backed guidance lookup, not a claim of autonomous clinical reasoning. Clinical review/quality acceptance remains pending until qualified review is performed; synthetic sources are excluded in production.

Server verifies the active DOCTOR principal and current consultation assignment, reads minimal facts from owning APIs, and never treats pageData/patient IDs from client as proof. Chat history is actor/consultation-scoped, encrypted with a separate content key, expiring; source version/hash, engine/model ID and context hash are retained for the same controlled retention window. Parent interaction cannot cross actor/consultation. Dependency failure does not create a success result. Source content is inert evidence, not executable instructions.

Sources: ADMIN imports a new version/excerpt; a DOCTOR explicitly reviews it before APPROVED. Retirement prevents new retrieval. Test import/review is not professional validation. Only source URL metadata links are exposed, never fetched from arbitrary user URL; no SSRF fetch pipeline.

Voice: browser microphone only on explicit action, max180seconds/20MiB, stopped on unmount/account/visit change; local ASR worker, no external audio upload. Save draft stops the microphone, creates/polls the job and calls Prescription's own idempotent AI-draft endpoint. No separate AI approval screen. Ambiguous medicine/conflicting evidence is corrected via transcript; incomplete but unambiguous draft fields remain blank, with signature blocked until completed. No guessed dosage/quantity.

Prescription owns draft creation/updates/signature. AI job/revision source link is durable and unique; retry returns the existing prescription, without overwriting later human edits. Unmapped voice fields have a named details field in Prescription items and remain editable. AI never calls clinical write APIs. Save failure remains failure; a succeeded AI job is not a saved prescription. Signing is a separate doctor action.

Schema: AI source/interaction tables alongside voice tables; Prescription item details and source-link table. DBML and canonical user guides updated with implementation. Tests cover auth, reassign/logout, duplicate/retry/concurrent save, evidence/no-guess, retention/encryption, source/model unavailability, source injection, mic lifecycle and actual source APIs/worker/browser. Real voice/professional evaluation and production readiness are stated separately.
