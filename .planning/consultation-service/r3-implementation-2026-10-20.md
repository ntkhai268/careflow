# R3 — implementation contract, 20/10/2026

Scope: R3-01–06 in the canonical full requirements plan. Backend/web continue on security-integration; native on patient-mobile-ios-login. R2 hardware acceptance remains open independently; proceeding with R3 is the user's explicit instruction. No AI/VNPT/Resend configuration changes, no commits, no shared remote test data resets.

## Intended behavior

- Assigned doctors list/read/download patient-uploaded records in the clinical page through authenticated endpoints. Patient remains the owner of uploaded documents; EMR retains its clinical master/aggregation responsibilities. Explicit error/empty states, no tokens in download URLs, no third-party viewer, and session changes cancel/discard downloads.
- Native upload matches the server PDF/JPEG/PNG limits, supports cancellation/progress, uses date-only JSON, and prevents stale callbacks/cache after account changes. Existing authenticated native open/share remains; hardware acceptance is reported separately.
- Follow-ups require a selected real available slot and the doctor's actual Directory clinical context. No implicit Internal Medicine/09:00 defaults. Source consultation and durable idempotency remain mandatory; retry cannot change an already-created booking silently.
- Prescription confirmation commits the signed prescription and a durable broker outbox together. Follow-up delivery is a separate authenticated operation, retaining signed state on dependency failure and exposing pending/failed/scheduled states. Retry uses current clinical authority; no stored user token or background impersonation.
- Consultation completion is idempotent after verifying the current doctor. Completion events use a durable outbox; Queue/Appointment completion can be retried from persisted visit IDs after partial failure. The UI must show partial progress instead of claiming success while discarding downstream errors.
- No lab result is silently marked reviewed merely by completing a visit. Required-result/review/signature guards remain authoritative. No-CLS, CLS return to the same visit, handover revocation and a new follow-up visit require actual API/web verification.

## Implemented decisions

- Prescription owns migrations V1 baseline/V2 release plan and delivery outbox. `POST /prescriptions/{id}/release` commits **CONFIRMED** plus event before attempting a separate authenticated follow-up transaction; compatibility `/confirm` only confirms. Status **SIGNED** is not an API enum. Follow-up command fields are `recommendedDate`, `department`, `timeSlot`, `consultationId`, `patientId`; response contains the actual booking ID. Old dated prescriptions without a selected slot are NEEDS_SELECTION.
- Consultation V6 persists completion outbox. `POST /consultations/{id}/finalize` returns clinical state plus per-step completion/pending flags. Retries resolve initial/review queue entries from durable source IDs and do not repeat completion events. Appointment exposes `POST /appointments/clinical-completion`, validating completed consultation/current doctor/source binding before normal status update. Caller scopes are exact endpoints, not unsupported mid-path wildcard patterns; no broad status-update scope is granted.
- Lab V3 adds original queue source, source audit, optimistic version and outbox. ORM-generated IDs are left unset at creation; assigning UUIDs before persist with nullable `@Version` caused real detached-entity failures and is covered by genuine JPA/PostgreSQL regression. Ready/result events preserve source; outbox deduplicates aggregate/type and reuses event ID on replay.
- Queue rejects result-review creation without exact source or an already-bound original consultation; it does not guess the latest visit of a patient. Minimal assignment metadata endpoint verifies the caller's actual room and INITIAL phase without relaxing the stricter start-consultation endpoint. Walk-in handover checks this persisted source, patient/visit and room; legacy queue rows without department code still require actual room matching and Directory same-department/room constraints. Null department metadata is not interpreted as a new assignment.
- Explicit lab review and no-current-author-draft/diagnosis guards protect completion. An inherited old-author draft remains read-only and is not silently reassigned, signed or cancelled. Patients use their authorized per-patient lab endpoint and filter by exact consultation for walk-in outcomes.
- Transactional outboxes rely on publisher confirms, mandatory routing and persistent messages; consumers remain responsible for deduplication. Broker retry does not claim push delivery. Physical viewer/share, native background push and every multi-order/multi-round CLS combination are not accepted by these technical checks.
